# 发行版本维护规则

继承仓库和editions/insights的AGENTS。先读本目录README、registry.json、shared/content-baseline.json和最新发行评审记录。

1. `essential`是内容版型；`cossi`、`community`是发行版本；`zh-CN`、`en`是语言；PDF/Web是输出格式。不得把它们混成单一版本轴。
2. 保留作者指定的COSSI发行名称，机构缩写仍为CCOSI，禁止全局替换。
3. Community基线明确是此前四Logo v1.4；COSSI两Logo历史基线为v1.6，当前中文v1.7、英文v0.6已登记。冻结成品记录不能随之后修订静默改写。新修订登记新版本和共同正文ID。
4. 共同正文、数据、图号、引用和证据只维护一套。发行专属差异限制在封面、前置内容、署名和发行信息；涉及正文变化时需变更共同内容基线并说明同步范围。
5. 各发行版本的英文版未完成前保持planned，成品、页数和发布日为空；构建入口必须拒绝输出伪英文版。
6. PDF、字体、原始附件和压缩包继续留在仓库外；不得把PDF改后缀或编码写入源文件。外部输入使用参数与SHA-256核验。
7. 不将编辑接受、机构牵头、社区共建写成联合国背书或全量数据验证。发布日和发布授权独立记录。
8. 修改后运行check_registry.py、精要版sources检查与两套品牌检查。构建器变更需复核所修改的可用路线；Community英文仍须拒绝，COSSI英文已可用；不自动部署Web。
